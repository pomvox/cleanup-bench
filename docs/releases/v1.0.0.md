## What this release is

The first frozen item set and the first committed rows of Cleanup Bench, a
public benchmark for dictation cleanup: the text-to-text layer that turns a
raw speech-recognizer transcript into what the speaker meant. The contract is
`docs/spec.md`; the rules are `GOVERNANCE.md`; the mechanics of a submission
are `SUBMITTING.md`.

Items are frozen at this tag. The item file hash recorded in every manifest
is `<from command: cleanupbench validate>` (also printed in
`site/leaderboard.json` under `items_sha256`).

There is no overall score and no ranking.

## Failure analysis of SimpleWords v3

GOVERNANCE.md, conflict-of-interest rule 3: our model's failures stay on the
board and each release's notes include a failure analysis of our rows.

For each SimpleWords v3 row (the engine row and the mlx-lm row), list every
item where the row

- lost a word (`word_loss` greater than zero),
- inserted a word (`insertion` greater than zero),
- over-cleaned a noop item (`noop: true` and `over_clean: true`), or
- fell back (`status: fallback`, with `fallback_reason`),

verbatim from the `items` array of that row's `scores.json`: the item `id`,
the `category`, and the fields named above as they appear in the file. Do
not summarize, group or omit; do not add a count that the file does not
contain. Where the two SimpleWords rows disagree on an item, say so and link

## How to replay

```
git clone https://github.com/pomvox/cleanup-bench
cd cleanup-bench
git checkout v1.0.0
uv sync
uv run cleanupbench validate
uv run cleanupbench score --check
uv run cleanupbench report --check
```

To regenerate a row's outputs from the system, follow `SUBMITTING.md`
section 2 with the adapter and config recorded in that row's `run.json`; the
Mac Studio runbook (`docs/MAC_STUDIO_RUNBOOK.md`) carries the commands for
the rows that need a model.
